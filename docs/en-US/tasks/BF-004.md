# BF-004 — Repeatable fictitious seed

[Português (Brasil)](../../pt-BR/tasks/BF-004.md)

## Objective and context

Provide a fictitious demo shop using the BF-003 validated schema/migration without duplicating or overwriting records on repetition.

## Scope

36 fixtures spanning ten models, fixed IDs/dates, fictitious contacts, Prisma hook/db:seed CLI, advisory-lock transaction, identity/final-record checks, production guard, seven seed tests and bilingual documentation. No schema or migration changes.

## Out of scope

Authentication, passwords, real personal data, message delivery, CRUD, calendar UI, inactivity calculations, resets and automatic demo removal. Next: BF-005, authentication and shop authorization.

## Acceptance criteria

- Official db:seed creates 36 valid fictitious records after migrations.
- Repetition preserves IDs, counts and content, including timestamps and manual edits.
- Concurrent execution is serialized and other shops' data is preserved.
- Identity/booking collisions fail with full rollback and no silent partial success.
- NODE_ENV=production blocks execution before connecting; errors never disclose credentials.
- Dates are fixed, consent starts false, emails use .invalid and phones use NANPA's fictitious range; no passwords or message delivery.
- 18 integration tests, the unit test, quality and build pass; CI runs the command twice and the complete suite.
- pt-BR/en-US documentation explains content, repetition, tests and limitations.

## Validation

Completed locally. All 18 integration tests and the unit test passed, including seven new seed scenarios. Lint, types, formatting and a credential-free build passed. The official db:seed command succeeded twice. CI runs quality, build, repeated seed and the database suite; its result is checked after publication. BF-003 dependency findings remain documented.
