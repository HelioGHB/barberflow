# BF-002 — Configure Prisma and PostgreSQL

[Português (Brasil)](../../pt-BR/tasks/BF-002.md)

## Objective and context

Connect the BF-001 Next.js project to PostgreSQL through Prisma and prepare the repository for GitHub with pt-BR/en-US documentation, as requested by the user. Initial state for this task: validated BF-001 foundation, without Git, a schema or database configuration.

## Scope

Prisma 7.10.0, PostgreSQL adapter, model-free schema, environment configuration, reusable server-only client, local Compose, `SELECT 1` diagnostic, configuration tests, bilingual README/docs, contribution templates and CI. Initialize Git and configure the supplied remote `https://github.com/HelioGHB/barberflow.git`.

## Out of scope

Business models, migrations, seeds, authentication, CRUD, product UI translations, application deployment and destructive database changes. Do not publish credentials or generated code.

## Relevant files

package.json, package-lock.json, prisma.config.ts, prisma/schema.prisma, src/lib, scripts/check-db.ts, tests/database-url.test.ts, compose.yaml, .env.example, .gitignore, .github, README.md, README.pt-BR.md and docs/{pt-BR,en-US}.

## Acceptance criteria

- Prisma validates the PostgreSQL schema and generates a client without fictitious models.
- Clean installation, generation and builds work without DATABASE_URL or a running database.
- Client access is protected by `server-only` and connections are reused during hot reload.
- Missing/invalid URLs fail with messages that do not disclose credentials.
- Compose provides healthy PostgreSQL bound only to loopback with a persistent volume.
- `db:check` succeeds against real PostgreSQL and exits nonzero for missing configuration.
- Lint, types, formatting and configuration tests pass.
- README, documentation, templates and CI cover pt-BR and en-US.
- Git ignores `.env`, artifacts and generated client; the remote contains no token.
- Existing remote content is checked before pushing, without force pushes.
