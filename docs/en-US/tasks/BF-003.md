# BF-003 — Initial schema and migrations

[Português (Brasil)](../../pt-BR/tasks/BF-003.md)

## Objective and context

Model initial entities and apply a PostgreSQL migration enforcing referential integrity, valid data and concurrent overlap prevention. BF-002 provides Prisma 7.10.0, a server-only client, local PostgreSQL and CI; the local database was empty before this stage.

## Scope

User, Barbershop, Barber, Customer, Service, Appointment, BusinessHour, BlockedPeriod and CustomerReminder, plus BarbershopMember for per-shop roles. UUIDs, UTC timestamps, integer-cent prices, indexes, shop-scoped composite foreign keys, checks and GiST exclusions. Transactional migration, status/drift commands, isolated integration suite and updated CI. pt-BR/en-US guides.

## Out of scope

Seed (BF-004), authentication, endpoints, CRUD, availability against hours/blocks, message delivery, product UI internationalization and deployment. No database/volume resets. Do not edit applied migrations.

## Acceptance criteria

- Validated Prisma schema and generated client with ten models.
- Migration applies to an empty database; repeated deployment makes no changes and leaves no pending migrations.
- Per-shop roles and entity references are verified in PostgreSQL.
- Invalid values and parent deletion affecting history are rejected by the database.
- Appointments preserve service snapshots and reject overlapping inserts/updates, including actual concurrency; adjacent slots and different barbers are allowed.
- Cancellation releases a slot; completion/no-show retain historical occupancy.
- Business hours support multiple daily intervals, weekdays 0–6 and midnight endings without overlap.
- The suite requires a separate test database, performs no resets/truncates and cleans only its UUID-scoped fixtures.
- Quality, unit test, build and database checks pass; documentation and CI are updated in both languages.

## Decisions and limits

One role per user/shop; OWNER and ADMIN may also be barbers. E.164 phone identifies a customer within a shop; the same number can exist in another shop. MVP prices use BRL cents. Overnight hours are split. Blocks may overlap. Rules depending on other entities (consent, hours/blocks and transitions) still need backend services in planned stages. There is no RLS or session authorization yet.

CHECKs/exclusions and the timezone function live in the migration's custom SQL; Prisma drift does not cover them. btree_gist must be available. The ORM maintains updatedAt, without a trigger. See database.md for details.
