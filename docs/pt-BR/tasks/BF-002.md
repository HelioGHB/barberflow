# BF-002 — Configurar Prisma e PostgreSQL

[English (US)](../../en-US/tasks/BF-002.md)

## Objetivo e contexto

Conectar o projeto Next.js da BF-001 ao PostgreSQL com Prisma e preparar o repositório para GitHub com documentação pt-BR/en-US, conforme solicitado pelo usuário. Estado inicial desta tarefa: base BF-001 validada, sem Git, schema ou banco configurado.

## Escopo

Prisma 7.10.0, adaptador PostgreSQL, schema sem modelos, configuração de ambiente, cliente exclusivo do servidor e reutilizável, Compose local, diagnóstico `SELECT 1`, testes de configuração, README e documentação nos dois idiomas, templates de contribuição e CI. Inicializar Git e configurar o remoto fornecido `https://github.com/HelioGHB/barberflow.git`.

## Fora do escopo

Modelos de negócio, migrations, seed, autenticação, CRUD, traduções da interface, deploy da aplicação e alterações destrutivas no banco. Não publicar credenciais nem código gerado.

## Arquivos relevantes

package.json, package-lock.json, prisma.config.ts, prisma/schema.prisma, src/lib, scripts/check-db.ts, tests/database-url.test.ts, compose.yaml, .env.example, .gitignore, .github, README.md, README.pt-BR.md e docs/{pt-BR,en-US}.

## Critérios de aceitação

- Prisma valida o schema PostgreSQL e gera cliente sem modelos fictícios.
- Instalação limpa, geração e build funcionam sem DATABASE_URL ou banco ativo.
- Acesso ao cliente está protegido por `server-only` e reutiliza conexões durante hot reload.
- URL ausente/inválida falha com mensagem que não expõe credenciais.
- Compose disponibiliza PostgreSQL saudável apenas em loopback, preservando volume.
- `db:check` passa com PostgreSQL real e retorna saída não zero diante de configuração ausente.
- Lint, tipos, formatação e testes de configuração passam.
- README, documentação, templates e rotina CI cobrem pt-BR e en-US.
- Git ignora `.env`, artefatos e cliente gerado; remoto não contém tokens.
- Conteúdo remoto existente é verificado antes de envio, sem push forçado.
