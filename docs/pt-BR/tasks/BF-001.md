# BF-001 — Inicializar projeto

[English (US)](../../en-US/tasks/BF-001.md)

## Objetivo e contexto

Criar uma base executável do BarberFlow no diretório vazio, seguindo a stack do documento de referência. Estado inicial: sem arquivos ou Git local.

## Escopo

Next.js App Router, React, TypeScript strict, Tailwind CSS, ESLint, Prettier, lockfile npm, scripts de desenvolvimento e validação, página inicial responsiva em português e documentação mínima de arquitetura, API, banco, desenvolvimento e roadmap.

## Fora do escopo

Banco, autenticação, CRUD, agendamento, dados demonstrativos de operações, PWA, deploy e serviços externos. Não instalar dependências para funcionalidades futuras.

## Arquivos relevantes

package.json, package-lock.json, tsconfig.json, next.config.ts, eslint.config.mjs, .prettierrc.json, src/app, README.md e docs.

## Critérios de aceitação

- Projeto instala com `npm ci` em Node.js 24.
- `npm run lint`, `npm run typecheck` e `npm run format:check` passam.
- `npm run build` gera artefatos de produção.
- Servidor de produção responde HTTP 200 em `/`, com título BarberFlow e idioma pt-BR.
- Página usa layout móvel de uma coluna e grade em telas maiores, sem controles que prometam funcionalidades inexistentes.
- Segredos e artefatos gerados são ignorados; `.env.example` pode ser versionado.
- Documentação distingue implementação atual de planos futuros.

## Validação

Status: CONCLUÍDA. Revisão: APROVADO COM AJUSTES de acompanhamento das dependências de desenvolvimento.

- Instalação limpa `npm ci`: passou. Plugin Tailwind substituído depois pelo oficial PostCSS; lockfile atualizado pela instalação npm.
- `npm run lint`, `npm run typecheck`, `npm run format:check`: passaram.
- `npm run build`: passou usando Webpack, gerando `/`, `/_not-found` e `/icon.svg`.
- Servidor de produção: HTTP 200 em `/`, título BarberFlow, idioma pt-BR, aviso de indisponibilidade das funcionalidades, âncora interna, CSS compilado e ícone HTTP 200; rota inexistente HTTP 404.
- Auditoria de produção: zero vulnerabilidades. Auditoria completa: cinco alertas na cadeia do ESLint, sem correção compatível publicada. Detalhes em docs/pt-BR/development.md.

A primeira tentativa de build com Turbopack falhou por restrição de porta interna do ambiente. Webpack resolveu a compilação sem trocar a stack. A primeira requisição HTTP foi bloqueada pelo sandbox; passou com permissão de acesso local.

Nenhum teste automatizado de regras de negócio se aplica, pois esta tarefa não implementa essas regras. Layout responsivo está definido em CSS; não houve inspeção visual em navegador nem em Android real. Não houve deploy ou criação de remoto Git.
